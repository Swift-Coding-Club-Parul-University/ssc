# Progress Log — October 1, 2026

## Bug: duplicate rows in the Google Sheet

### Root cause
The Google Sheets webhook fired **before** any validation or persistence:

1. `public/src/js/app.js` (`executeSubmission`) POSTed to the Apps Script webhook
   immediately after building the row — **before** the Turnstile CAPTCHA check and
   **before** `/api/register` ever ran.
2. Every user-facing failure (429 rate limit, 409 duplicate email, CAPTCHA failure,
   500, network drop) re-enabled the Submit button, inviting another attempt.
3. Each attempt appended another row to the sheet. Supabase protected itself via
   the `email UNIQUE` constraint, but the sheet had no dedupe and no unique key.

Net effect: one rejected registration could produce many sheet rows.

### Fix
Made the sheet a **post-success, server-side** write:

- **`public/src/js/app.js`** — removed the client-side webhook block
  (`sheetWebhookUrl`, `sheetPayload`, the `no-cors` fire-and-forget fetch).
  The browser no longer writes to the sheet at all.
- **`api/register.js`** — added a Sheets relay that runs only after a successful
  Supabase insert (before the email block, so the 450/day quota-shield early
  return cannot skip it):
  - identical camelCase payload as before, plus `original_id` (row id) and
    `submittedAt` for downstream dedupe
  - 5s `AbortController` timeout; failures are logged and **never** fail the
    registration
  - URL reads `process.env.SHEET_WEBHOOK_URL`, falling back to the original
    hardcoded webhook (production behaviour unchanged)

### Resulting flow
```
rate limit -> CAPTCHA -> Supabase insert (UNIQUE email) -> sheet relay -> email -> respond
```
Because `email` is `UNIQUE`, at most one insert can ever succeed per person, so at
most **one** sheet row can ever be written per person — retries and rejections
now exit before the relay.

### Verification
- `node --check` on both changed files
- Local echo server bound to `SHEET_WEBHOOK_URL`: rejected submissions
  (missing CAPTCHA / unconfigured credentials) produce **zero** webhook hits
- Deploy check pending: one test signup -> exactly 1 sheet row; same email again
  -> 409, still 1 row
